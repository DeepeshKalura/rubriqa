derived from the measured cells above
  • Path C is more accurate, Path A is cheaper — the data does not settle which to default to. C has the lower mean CER (77.0% vs 79.3%) at $0.00620/page; A costs $0.00466/page. That is 33% cheaper for a 2.3 CER-point difference — and on 11 pages neither difference is statistically significant (issue #6). Treat this as a cost decision, not an accuracy claim.
  • Do not run Path B as the production path. It never won a contested CER comparison (0 real wins), and its OCR is the failure mode — on some pages it returns nothing at all, yet still scores because the prefilled form fields are present. That is a *scoring* result with no reading behind it.
  • Escalate, don't choose once. The evidence supports running Path A first and escalating to Path C only when A's legibility or CER is poor — the fusion gate already does this for noise detection. On 11 pages the mean gap is not statistically separable (issue #6), so a single fixed path for every page is not yet justified by data.
  • Fix disk before scale. 50.5 GB for 25,000 pages. The API bill for the whole run is smaller than the storage it needs.

Key findings

read this first
  • M3.1-Flash-Preview read no page images at all — its vision paths (A and C) returned empty text on every run. Verified against the live API: it answers text prompts, but it cannot disable its reasoning preamble and it rejects full-page image payloads. The thinking block consumes the whole max_tokens budget, the response ends with finish_reason: length, and message.content is empty. It can still work on Path B only, where Tesseract does the OCR and the model merely scores — and it is slower per run than M3 while doing it.
  • MiniMax-M3 is the only model in this matrix that actually reads pages. Every OCR number below comes from it.
  • Wins marked +N* are wins by absence — the cell was the only one that produced any text, so it cannot be called a real win. They are excluded from the headline count.
  • Latency projections use p95, not the mean. The p95 tail is brutal: path A's median is ~25s while its p95 is minutes on hard pages. A mean-based 25k projection understates wall clock several-fold.
  • Disk, not API cost, is the binding constraint: 50.5 GB needed for 25,000 pages at 2.07 MB/page (originals only).
  • Page-to-page variance dominates everything. Per-page CER spans ~9% to ~200%, which is why 11 pages cannot statistically separate the paths — see issue #6.
